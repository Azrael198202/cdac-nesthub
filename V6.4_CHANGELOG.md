# v6.4 Executor LLM Generation Real Fix

## Fixed

- Locked `content_generation` / `llm_generate` execution now stops at the executor LLM path.
- If executor LLM does not return `answer_material`, the step is blocked with `content_generation_failed`.
- `content_generation` no longer falls through to runtime observation, web/API, module registry, or prompt/contract fallback.
- The output executor rejects internal prompt/contract/debug text as final answer.
- `answer_material` is lifted to both top-level result and `data.answer_material` so synthesis/delivery can reliably find it.

## Quality checks

- Python compile validation passes.
- Unit simulation confirms successful content generation returns `answer_material`.
- Unit simulation confirms missing `answer_material` blocks and does not fallback.
- Unit simulation confirms final delivery refuses prompt-contract text.
