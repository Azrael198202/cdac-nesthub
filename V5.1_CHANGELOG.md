# v5.1 Agent Action Planning

## Core change

This version separates two different meanings of LLM usage:

- `planner_llm`: used by `workflow_planning` and `agent_action_planning` to plan topology, rank fixed actions, and generate substeps. Its output is not final answer material.
- `executor_llm`: used only when `agent_action_planning` explicitly selects `llm_generate` as the locked action type.

## Pipeline change

Added `agent_action_planning` between `workflow_planning` and `execution_preparation`.

```text
workflow_planning
  -> agent_action_planning
  -> execution_preparation
  -> pre_execution_validation
  -> execution
```

## Rules

- `workflow_planning` only creates the main workflow, agent graph, dependency relation, and agent objectives.
- `agent_action_planning` ranks fixed action options and locks the final action type for each agent/substep.
- `execution_preparation`, `pre_execution_validation`, and `execution` now read the locked action plan from `agent_action_planning`.
- `execution` is not allowed to reselect execution methods.
- Planner LLM output cannot enter `final_synthesis`.

## Fixed action options

- `llm_generate`
- `generate_code`
- `generate_shell`
- `call_api_no_key`
- `call_api_with_key`
- `web_query`
- `use_existing_tool`
- `use_external_skill`
- `use_local_knowledge`
- `generate_complex_tool`
- `compose_static_response`
- `ask_user`
- `no_op`
