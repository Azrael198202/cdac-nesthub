# v5.6 Agent Flow and Locked Routing

## Goals
- agent_action_planning must output the agent execution flow, not only a single action.
- Planner LLM is used for choosing actions, discovering candidate sources, and designing resource contracts, not for executing the user task unless llm_generate is explicitly selected.
- web_query/api_call must preserve target/query/endpoint references as evidence material.
- execution must not route web/api actions into runtime-native observation.
- final output must not publish failed verification material.

## Changes
- Extended fixed action prompt contract with agent_execution_flow requirements.
- Added default domain-neutral agent execution flow generation.
- Added flow preservation into execution_preparation resource_bundle.
- Added web/api evidence URL policy into resource_bundle.
- Added locked action method enforcement before execution.
- Skipped runtime-native observation branch for web_search/api_call methods.
- Strengthened result verification for external resource methods by requiring source/provenance evidence.
- Output executor no longer uses final_synthesis.final_answer when result_verification failed.
